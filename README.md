# EIC Club Dashboard

Event-tracking and member-analytics dashboard for a university
**Entrepreneurship & Innovation Cell (EIC)** — a REST API plus a small
multi-page front end that gives club leads a live view of membership
growth, event attendance and branch participation, plus an RFID-based
check-in scanner for taking attendance at meetings.

**Stack:** Node.js · Express · vanilla JS/HTML/CSS (no front-end framework) · Chart.js

🔗 **Live demo:** _deployed on Vercel_ — see [Deployment](#deployment)

---

## What it does

Three pages, sharing one nav bar:

- **Overview** (`/`) — KPIs, member-growth trend, attendance trend,
  event-category breakdown, branch breakdown
- **Members** (`/members.html`) — searchable/filterable directory
  (branch, role, active status); add new members
- **Attendance scan** (`/attendance.html`) — take attendance at a meeting
  by scanning members' RFID cards; live running list + count of who has
  checked in for the selected meeting

Data is generated by a seeded PRNG on startup (240 members, 28 events spread
over ~2 years) so every run gets realistic, stable numbers with no database
or credentials required. POSTs mutate the in-memory store for the life of
the process.

### RFID attendance scanning

Every member is seeded with a fake RFID tag UID (not exposed over the API).
A USB RFID reader behaves as a keyboard — it "types" the scanned card's UID
into whatever's focused, then presses Enter — so the scan page is just a
focused text input: leave `/attendance.html` open on a check-in laptop
plugged into a reader and scans check members in with no extra integration.
No reader handy? The page also has a **simulate tap** control that checks a
chosen member in the same way, for demoing the flow without hardware.

## API

| Endpoint | Method | Description |
|---|---|---|
| `/api/health` | GET | liveness check |
| `/api/members` | GET | list members, filter by `branch`, `role`, `active` |
| `/api/members` | POST | add a member (`name`, `branch` required) |
| `/api/events` | GET | list events, filter by `category`, `from`, `to` |
| `/api/events/:id` | GET | single event |
| `/api/events` | POST | add an event (`title`, `category`, `date` required) |
| `/api/attendance/:eventId` | GET | check-in log + count for a meeting |
| `/api/attendance/scan` | POST | check a member in by scanned RFID tag (`eventId`, `rfidTag`) |
| `/api/attendance/simulate` | POST | check a member in by id, no card needed (`eventId`, `memberId`) |
| `/api/stats/overview` | GET | headline KPIs |
| `/api/stats/member-growth` | GET | cumulative members by month |
| `/api/stats/attendance-trend` | GET | per-event attendance |
| `/api/stats/event-categories` | GET | events + attendance by category |
| `/api/stats/branch-breakdown` | GET | member count by branch |

## Run it locally

```bash
npm install
npm start                 # serves the API + dashboard at http://localhost:3000
npm run dev                # same, with --watch for auto-reload
npm test                   # runs the API smoke tests (node --test)
```

## Deployment

Configured for zero-config deploy on [Vercel](https://vercel.com):
`vercel.json` rewrites `/api/*` to the serverless entry point
`api/index.js`, which re-exports the Express app; static assets in
`public/` are served directly.

1. Push this repo to GitHub.
2. On Vercel → **New Project** → import this repo → deploy (no env vars needed).

## Project layout

```
src/app.js               Express app factory: middleware, /api mount, static files
src/routes/api.js        REST routes for members / events / attendance / stats
src/data/store.js        seeded mock data + analytics + attendance helpers (in-memory)
api/index.js             Vercel serverless entry (wraps src/app.js)
public/index.html        Overview page (charts + KPIs)
public/members.html      Members directory page
public/attendance.html   RFID attendance scan page
public/js/               per-page vanilla JS (app.js, members.js, attendance.js)
test/api.test.js         smoke tests (node --test)
```

## Notes & limitations

- In-memory data store — restarting the process resets any POSTed data;
  there's no database or auth layer, by design, since this is a portfolio
  demo rather than a production club-management system.
- Mock data is generated with a fixed seed, so member/event names are
  synthetic, not real club records.
- RFID tags are simulated (random hex UIDs assigned server-side) — there's
  no real reader/hardware integration, but the scan flow is built the way a
  real USB HID RFID reader is wired up, so swapping in real hardware would
  need no changes to this app.
